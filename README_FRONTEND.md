# Фронтенд «Лист Поднебесной»

Интернет-магазин китайского чая. Фронтенд работает на **Next.js App Router**, данные получает из отдельного Laravel API.

## Быстрый старт

Нужен Node.js **20.9 или новее**. Все команды запускайте из корня фронтенда — папки, где находится `package.json`.

```bash
npm install
npm run dev
```

Откройте адрес, показанный в терминале (обычно `http://localhost:3000`). Для подключения API создайте `.env.local` в корне и укажите публичный адрес сервера:

```env
API_UPSTREAM_URL=http://127.0.0.1:8000/api
```

`API_UPSTREAM_URL` используется только сервером Next.js. На время миграции BFF также понимает старую переменную `NEXT_PUBLIC_API_URL`, но для новой настройки используйте `API_UPSTREAM_URL`. Никогда не добавляйте секреты или пароли в `NEXT_PUBLIC_*`: эти переменные встраиваются в браузерный код.

## Частые задачи

| Нужно сделать | Где искать |
| --- | --- |
| Добавить URL или страницу | `src/app/<путь>/page.jsx` |
| Изменить экран каталога, блога, профиля и т. д. | `src/features/<раздел>/pages/` |
| Изменить бизнес-состояние корзины, входа или избранного | `src/features/<раздел>/model/` |
| Переиспользовать общий компонент | `src/shared/ui/` |
| Изменить запросы к API | `src/shared/api/api.js` и нужный feature |
| Добавить общую расчётную функцию | `src/shared/lib/utils/` |
| Изменить общие цвета и оформление | `src/shared/styles/`, `src/app/globals.css` |
| Изменить общую оболочку или провайдеры | `src/app/layout.js`, `src/app/providers.jsx` |

### Как добавить страницу

1. Создайте маршрут, например `src/app/promo/page.jsx`.
2. Создайте экран `src/features/promo/pages/PromoPage.jsx` и поместите туда интерфейс страницы.
3. Импортируйте экран в `page.jsx`. Стили страницы положите рядом с экраном в CSS Module (`PromoPage.module.css`).

Маршрут `/tea/название-чая` уже показывает пример динамической страницы: `src/app/tea/[slug]/page.jsx`. Значение `[slug]` — часть URL, которая меняется для каждого товара.

## Как устроен проект

```text
src/
├── app/                  # URL-маршруты и общая оболочка Next.js
├── features/             # экраны и логика отдельных разделов магазина
│   ├── admin/            # управление магазином
│   ├── auth/             # вход, регистрация и авторизация
│   ├── blog/             # статьи и категории
│   ├── cart/             # корзина
│   ├── catalog/          # каталог и карточка чая
│   ├── checkout/         # оформление заказа
│   ├── content/          # FAQ и контакты
│   ├── favorites/         # избранное
│   ├── home/              # главная страница
│   └── profile/           # личный кабинет
└── shared/                # общий код, используемый разными разделами
    ├── api/               # клиент Laravel API
    ├── lib/utils/         # общие функции и расчёты
    ├── styles/            # общие стили
    └── ui/                # общие компоненты интерфейса
```

**Простое правило:** `app` отвечает за адрес страницы, `features` — за содержимое и логику раздела, `shared` — за код, который нужен нескольким разделам.

## Важные правила Next.js

- В `src/app` размещайте маршруты (`page.jsx`), layout и обработку ошибок. Большой экран и его бизнес-логику держите в `features`.
- Компоненты по умолчанию являются Server Components. Добавляйте `'use client';` в начало файла, только если компоненту нужны React-хуки, обработчики событий, контексты или браузерные API (`localStorage`, `window`, `document`).
- Для внутренних ссылок используйте `Link` из `next/link`. Для перехода после действия — `useRouter` из `next/navigation`. Для сегментов динамического URL — `useParams`.
- `PrivateRoute` и `AdminRoute` управляют тем, что пользователь видит в интерфейсе. Laravel API всё равно должен проверять разрешения перед выполнением запроса: клиентская проверка сама по себе не защищает данные.
- Общие вызовы API выполняйте через настроенный Axios-клиент `src/shared/api/api.js`, а не создавайте отдельный клиент в каждой странице.
- Браузер обращается к `/api/*` на том же домене. Next.js проксирует запрос к Laravel; токен хранится в HttpOnly-cookie и добавляется к запросу только на сервере. Не читайте и не сохраняйте токены в `localStorage`.
- Расчёты, повторно нужные нескольким разделам, размещайте в `src/shared/lib/utils`, например расчёт веса чая или стоимости доставки.

## Комментарии и подсказки VS Code

У важных файлов и экспортируемых функций есть JSDoc-комментарии: они объясняют назначение, применение и работу кода, а также содержат примеры. Чтобы открыть подсказку, наведите курсор на имя импортированной функции/компонента или на вызов, например `useCart()`. Наведение на имя файла в проводнике VS Code не показывает комментарий из его содержимого.

## Коммиты Git

Используйте формат **Conventional Commits**:

```text
тип(область): краткое описание
```

Описание пишите коротко и в одном выбранном языке. Начинайте с действия: `добавить`, `исправить`, `обновить`. Точку в конце не ставьте.

| Тип | Когда использовать | Пример |
| --- | --- | --- |
| `feat` | Добавляете новую возможность для пользователя | `feat(catalog): добавить фильтр по типу чая` |
| `fix` | Исправляете ошибку в существующем поведении | `fix(cart): учитывать остаток товара при добавлении` |
| `docs` | Меняете документацию или комментарии | `docs(frontend): описать структуру приложения` |
| `style` | Меняете форматирование кода без изменения поведения | `style(header): привести отступы к единому виду` |
| `refactor` | Перестраиваете код без изменения поведения | `refactor(auth): разделить логику входа и профиля` |
| `perf` | Улучшаете скорость или расход ресурсов | `perf(catalog): уменьшить число запросов товаров` |
| `test` | Добавляете или меняете тесты | `test(cart): проверить расчёт общей суммы` |
| `build` | Меняете сборку или зависимости проекта | `build(next): обновить конфигурацию сборки` |
| `ci` | Меняете автоматические проверки или pipeline | `ci: запускать lint перед сборкой` |
| `chore` | Прочие технические задачи обслуживания | `chore: удалить неиспользуемые файлы` |
| `revert` | Отменяете ранее созданный коммит | `revert: отменить добавление фильтра каталога` |

`область` необязательна: укажите раздел проекта (`cart`, `catalog`, `auth`, `admin`, `frontend`) или пропустите её, если изменение общее. Один коммит должен описывать одну понятную задачу.

Если изменение ломает совместимость, отметьте это восклицательным знаком и объясните в теле коммита:

```text
feat(api)!: изменить формат данных товара

Breaking change: потребителям API нужно читать цену из поля price_per_100.
```

### Перед коммитом

```bash
npm run lint
npm run build
git status
git diff --check
```

Проверьте список файлов и сам diff, затем создайте коммит с подходящим типом. В проекте нет отдельного npm-скрипта для тестов.

## Production-сборка

```bash
npm run build
npm start
```

Для production на Railway используется `next start`.
